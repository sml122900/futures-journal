## 결정 사항

| 결정 | 이유 |
|------|------|
| DB 큐 방식 (EmergencyScheduledAlert) | Vercel serverless 환경에서 in-memory 타이머 불가. DB 예약 + 매분 cron이 유일한 신뢰 가능한 방법 |
| `max(avg, median)` 기준값 | 평균만 사용 시 고액 이상치가 기준을 끌어올려 정상 큰 포지션도 발동 안 될 수 있음. 둘 중 큰 값으로 false positive 감소 |
| 30초 신규 포지션 임계값 | DB 캐시나 lastSeen 방식보다 단순. 진입 직후 30초가 알림 발동 의미 있는 구간 |
| activeHoursOnly는 서버 시간(UTC) 기준 | KST 변환 없이 UTC Hours 사용. 설정 UI에서 UTC 기준으로 안내 필요 (향후 개선) |
| customMessage를 LATER로 분리 | Phase E는 텔레그램 발동 로직 범위. customMessage는 크롬 확장(포지션 진입 시 브라우저 오버레이)과 연동 예정 |

|------|------|
| `Type 'EmergencyContext' is not assignable to 'JsonNull | InputJsonValue'` | `as unknown as Prisma.InputJsonValue` 두 단계 캐스팅 |
