### Phase 7 버그 수정 (3개)

#### 버그 1 (🔴): MarkdownV2 파싱 오류
- 문제: webhook에서 MarkdownV2 이스케이프(`\\!` `\\.` `\\-`) 사용 + `parseMode: "Markdown"` v1 발송 → 백슬래시 그대로 렌더링
- 수정: `telegram.ts` 타입에 `"MarkdownV2"` 추가, 기본값 변경, `notifications.ts` 전체 `"MarkdownV2"` 통일
- `notification-templates.ts`에 `esc()` 헬퍼 추가, 6개 템플릿 재작성 (동적 값 전부 이스케이프)
- `webhook/route.ts` 모든 메시지 MarkdownV2 수정

#### 버그 2 (🟡): 메모 리마인더 cron 로직 교체
- 문제: "메모 레코드가 있는데 내용이 빈 것"을 찾는 로직 — Memo는 사용자가 직접 저장해야 생성되므로 실질 동작 0건
- 수정: "어제 KST 날짜에 작성된 실질 메모가 없는 사용자"로 로직 교체
- KST midnight 계산: `new Date(Date.now() + KST_OFFSET)` → `setUTCHours(0,0,0,0)` → UTC 변환
- cron 스케줄 `"0 15 * * *"` → `"0 23 * * *"` (KST 08:00)
- 메시지: "어제 매매 기록을 아직 작성하지 않으셨네요" 형태로 교체

#### 버그 3 (🟡): 주간 리포트 pnlPercent 미전달
- 문제: `notifyWeeklyReport` 호출 시 `pnlPercent` 없어 퍼센트 미표시
- 수정: `reportContent.summary.totalPnlPercent` 추출 후 전달. 없으면 undefined → 템플릿이 생략 처리

## 결정 사항

| 결정 | 이유 |
|------|------|
| 텔레그램 연동 코드 방식 (6자리) | OAuth보다 단순, 10분 만료로 보안 충분, 봇과 상호작용 자연스러움 |
| MarkdownV2로 통일 | Markdown v1은 `.` `!` `-` 이스케이프 불필요 — 기존 `\\!` 문법과 혼용 시 백슬래시 노출. MarkdownV2 단일 표준으로 일관성 확보 |
| 메모 리마인더 = "어제 메모 없는 사용자" | 포지션은 DB에 없고 거래소 API에만 있어 cron에서 확인 불가. 메모 작성 여부로 간접 감지 |
| Binance fill 필터에 `oPosSide === side` 추가 | BinanceExchange.getOrders()가 `posSide: "long"|"short"` 반환 (Bitget의 `side: "buy"|"sell"` 과 다름) |
| 백테스트 후방 seek = 미래 거래 삭제 | lookahead bias 방지 일관성 유지. 미래 거래 보존 시 "이미 알고 있는 캔들에서 거래한" 결과를 역산하는 불합리한 상황 발생 |
