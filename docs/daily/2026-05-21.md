## 세션 8 — Emergency Brake 트리거 시스템 전면 재설계

---

## 배경

기존 7개 자동 트리거(UserBaseline 통계 기반 sizeMultiplier 비교)는 false positive가 많고, 사용자가 왜 발동됐는지 예측하기 어려웠음. 새로운 방향: "사용자가 직접 정의한 룰만 체크."

---

## 작업 내용

### 명령 1 — 분석 (코드 변경 없음)

기획 검토 보고서 작성:
- 시간대 처리(KST vs UTC) 엣지 케이스 식별
- #5 min_interval 데이터 소스 불명확 → `lastPositionEntryAt` 필드 추가 제안
- 다중 발동 통합 룰(1=L1, 2=L2, 3+=L3) 확정
- `TriggerViolation` 로그 테이블 추가 제안
- RestDeclaration vs NoTradeWindow 겹침 분석 → 별도 유지 결정

### 명령 2 — 서버 구현 (futures-journal)

**DB 스키마**
- `EmergencySetting` 모델 완전 제거 (기존 1행 삭제)
- 신규 4개 모델 추가:
  - `UserTriggerSettings`: 룰 4개 ON/OFF + 값 + forceSentence + lastPositionEntryAt
  - `NoTradeWindow`: 단발성 매매 금지 기간 (startAt/endAt UTC)
  - `RecurringNoTrade`: 반복 금지 시간대 (startHour/Min ~ endHour/Min KST)
  - `TriggerViolation`: 발동 이력 로그

**신규 파일**
- `src/lib/timezone-utils.ts`: KST 변환 헬퍼 (toKST, nowKST, isInTimeRange 자정 처리)
- `src/lib/trigger-checker.ts`: 6개 룰 체커 + TriggerViolation 자동 기록 + level 결정

**수정 파일**
- `src/lib/emergency-detector.ts`: stub으로 교체 (trigger-checker re-export)
- `src/lib/emergency-templates.ts`: EmergencyContext에 triggers 배열 추가, step1 메시지 새 포맷
- `src/lib/emergency-scheduler.ts`: EmergencyDecision → TriggerDecision 타입으로 교체
- `src/app/api/exchange/positions/route.ts`: checkAllTriggers 호출로 교체

**신규 API 라우트**
- `GET/PUT /api/trigger-settings`
- `GET/POST /api/no-trade-windows`
- `DELETE /api/no-trade-windows/[id]`
- `GET/POST /api/recurring-no-trade`
- `PATCH/DELETE /api/recurring-no-trade/[id]`
- `GET /api/extension/blocking-status`
- `GET/POST /api/emergency-check` (재작성)
- `GET /api/emergency-check/baseline` (UserTriggerSettings 반환으로 교체)
- `/api/settings/emergency` (410 stub)

**마이그레이션**: `npx prisma db push --accept-data-loss` 성공

### 명령 3 — UI 구현 (3개 프로젝트)

**futures-journal: settings/emergency 페이지 전면 재작성**
- 상단 차단 상태 박스 (빨간/녹색, 30초 폴링)
- 강제 타이핑 문장 섹션
- 6개 카드형 트리거 UI (ON/OFF 토글 + 값 입력 + 저장)
- 카드 2 (단발): 모달로 날짜+시간 추가, 리스트 표시/삭제
- 카드 3 (반복): 모달로 HH:MM 입력, 자정 넘어가는 범위 미리보기, 수정/끄기/삭제
- 다크모드 대응, 모바일 반응형

**futures-journal-extension: 차단 띠 + 폴링**
- `banner.js`: fixed 빨간 띠, 닫기(5분 TTL), update/clear API
- `content.js`: 초기 체크 + 5분 폴링 + background 메시지 수신
- `api-client.js`: `fetchBlockingStatus()` 추가
- `background.js`: blockingStatus 알람(5분), 활성 Bitget 탭에 메시지 전달

**futures-journal-android: 트리거 메시지 표시**
- `strings.xml`: 트리거 타입 6개 한글 레이블
- `EmergencyPayload.kt`: `triggerMessages: List<String>?` 추가
- `OverlayService.kt`: `buildTriggerText()` — 메시지 → 타입 레이블 → 배수 표시 순 fallback

## 결정 사항

| 결정 | 이유 |
|------|------|
| 통계 기반 트리거 → 사용자 정의 룰로 전환 | false positive 구조적 제거, 사용자 예측 가능성 |
| 시간대 KST 고정 (timezone 필드 없음) | 국내 사용자만 타겟, 코드 단순화 |
| 다중 발동: 1=L1, 2=L2, 3+=L3 | 발동 개수로 심각도 결정 — 기준 명확 |
| EmergencySetting 완전 제거 | UserTriggerSettings로 통합, 레거시 제거 |
| RestDeclaration 유지 | NoTradeWindow와 UX 차이(즉석 선언 vs 사전 예약) 존재 |
